# FT-008 — Workpiece genealogy and deterministic quality routes

FactoryTwin remains a **software-only synthetic simulator**. The quality results described here are scenario data generated by local configuration; they are not measurements from physical inspection equipment and do not validate a real manufacturing process.

## Scope and route semantics

FT-008 adds per-workpiece genealogy and deterministic quality outcomes without changing FT-007's graph contract. The production graph is still exactly one validated acyclic linear route. Each generated workpiece keeps one immutable ID and records station visits with entry, processing-completion and exit simulation ticks/times.

A station attempt resolves to one of three outcomes:

- `GOOD` — the operation succeeded. The item may transfer to the next linear station when its single downstream slot is free, or becomes a completed good unit at the final station.
- `SCRAP` — terminal outcome. The item leaves the line at the current station and increments `scrapped` exactly once.
- `REWORK` — the item repeats the **same station operation** with the same workpiece ID and an incremented attempt number. This is not a routing edge, does not send the item upstream, and does not weaken the blueprint's cycle/branch rejection.

Unspecified station attempts default to `GOOD`, preserving the pre-FT-008 production behavior. A local `QualityScenario` JSON file can deterministically override selected `(workpiece_id, station, attempt)` tuples. There is no random yield model.

## Genealogy model

Each workpiece record includes creation time, current/terminal status, rework count, terminal time when applicable, and ordered station visits. Each visit records:

- station ID and attempt number;
- `entered_tick` / `entered_sim_time_ms`;
- processing completion tick/time;
- `GOOD`, `SCRAP` or `REWORK` plus provenance (`default` or configured `scenario`);
- station exit tick/time.

The existing conservation rule remains:

`next_id - 1 == completed + scrapped + in_process`

`REWORK` never creates another workpiece and therefore does not affect conservation. `audit_genealogy()` performs a deeper consistency check over historical station order, attempts, terminal states and aggregate counters. The regular `validate()` path continues to enforce current-state invariants without rescanning the entire history every tick.

## Timing, backpressure and interlocks

Quality is evaluated only after a station consumes its configured number of **productive** ticks. Paused or faulted lines still advance observation ticks but do not process, apply quality outcomes, transfer, scrap, rework or create workpieces. A `GOOD` operation that is blocked by an occupied downstream slot remains completed at its current station and is not processed or quality-evaluated again while waiting.

Reset preserves the validated blueprint and quality scenario but clears the session's workpieces, genealogy and counters.

## Replay compatibility

- Legacy default runs with no quality decisions still export `factorytwin.trace.v1` unchanged in shape.
- Legacy custom-blueprint runs with no quality decisions still export `factorytwin.trace.v2` unchanged in shape.
- A non-empty quality scenario exports `factorytwin.trace.v3`, embedding the canonical blueprint, canonical quality scenario, operation journal and complete deterministic genealogy state.

Replay continues to accept v1/v2 and reconstructs their implicit all-good genealogy internally while comparing against their legacy final-state shape. v3 replay validates the scenario and full genealogy projection. No trace import endpoint is exposed over HTTP.

## Local API and UI

`GET /api/snapshot` retains its existing behavior and still advances an observation tick. The response adds quality/rework summaries and recent workpiece summaries. `GET /api/workpieces/<WP-ID>` is a new read-only genealogy endpoint and **does not advance** the simulation tick. Existing control endpoints and localhost-only binding remain unchanged.

The dashboard now displays good units, scrap, rework cycles and recent workpiece status. The sample `config/quality_scenario.json` demonstrates same-station rework and scrap on the configured `Feed → Inspect → Pack` line.

## Non-goals

FT-008 does not implement upstream routing loops, branching, merging, buffers larger than one, random defect/yield distributions, physical inspection hardware, calibrated process capability, persistence, OEE, or industrial control. Physical re-entry to an earlier station would require an explicit future graph/routing design rather than overloading this same-station rework model.
